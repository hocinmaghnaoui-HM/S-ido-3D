Säido Nuts — النسخة الاحترافية (Professional Edition)
========================================================

هذه النسخة مبنية لتعمل مباشرة على Cloudflare Workers (بعكس نسخة Replit
التي تحتاج Postgres + Express ولا تعمل على Cloudflare).

الجديد في هذه النسخة مقارنة بالنسخة السابقة:
- تصميم أسود قاتم + ذهبي مطابق للمتجر الأول بالكامل.
- لوحة تحكم بتبويبات: الإحصائيات، الطلبات، المنتجات، مناطق التوصيل.
- كل طلب يرسله الزبون عبر الموقع يُحفظ تلقائيًا في سجل الطلبات
  (تشوفه من لوحة التحكم)، بالإضافة لفتح واتساب كالمعتاد.
- رسوم توصيل قابلة للتخصيص لكل ولاية من الـ 69 ولاية، تُحسب تلقائيًا
  وتُضاف للمجموع الذي يراه الزبون قبل الطلب.
- لوحة إحصائيات: عدد الطلبات، الإيرادات، عدد المنتجات الظاهرة، وتوزيع
  الطلبات حسب الحالة (جديد / مؤكد / تم الشحن / تم التسليم / ملغى).
- كلمة مرور لوحة التحكم: maghnaoui03 (تُضبط كـ Secret، انظر الخطوة 3).

خطوات الإعداد (نفس خطوات النسخة السابقة، كررها إذا كان هذا مستودع جديد):
--------------------------------------------------------------------------

1) إنشاء قاعدة بيانات KV:
   - Cloudflare Dashboard > Storage & Databases > KV > Create a namespace
   - اسم مقترح: saido-products
   - انسخ الـ Namespace ID

2) عدّل wrangler.jsonc:
   - استبدل PUT_YOUR_KV_NAMESPACE_ID_HERE بالـ ID الذي نسخته
   - احفظ (commit) مباشرة على GitHub

3) أضف كلمة مرور لوحة التحكم كـ Secret:
   - صفحة الـ Worker > Settings > Variables and secrets > Add
   - الاسم: ADMIN_PASSWORD
   - القيمة: maghnaoui03
   - فعّل "Encrypt"، ثم احفظ

4) انتظر إعادة النشر التلقائي، أو اضغط Retry build من تبويب Deployments.

5) الدخول للوحة التحكم:
   - https://[نطاقك]/admin.html
   - كلمة المرور: maghnaoui03
   - من تبويب "مناطق التوصيل" حدد رسوم كل ولاية (اختياري، اتركها فارغة
     إن كان التوصيل موحّد السعر أو مجاني)

إذا رفعت هذا المشروع في نفس مستودع GitHub القديم المربوط بـ Cloudflare:
احذف كل الملفات القديمة أولًا، ثم ارفع محتوى هذا الـ zip كما هو في جذر
المستودع (بحيث يكون wrangler.jsonc في المسار الرئيسي مباشرة). الربط بين
GitHub و Cloudflare يبقى كما هو، ولا حاجة لإعادة ربطه.

إذا كان عندك KV namespace وSecret مضبوطين مسبقًا من النسخة السابقة:
لا حاجة لتكرار الخطوات 1 و3، فقط تأكد أن نفس الـ Namespace ID موجود في
wrangler.jsonc الجديد (انسخه من النسخة القديمة إن كان مختلفًا).
